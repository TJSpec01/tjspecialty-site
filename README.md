# tjspecialty.com

Static website for **TJ Specialty Construction, LLC** — Brainerd Lakes area, Minnesota.

Migrated off Wix. No CMS, no database, no build server: plain HTML/CSS/JS generated by a
small Node script and served straight from GitHub Pages.

---

## Repository layout

```
build.js              # generator — run this after any content change
src/
  site.js             # business details, navigation, form endpoint
  content.js          # all page copy, section by section
  layout.js           # page shell + block renderers
assets/
  css/site.css        # all styling
  js/site.js          # mobile nav, dropdowns, gallery lightbox
  img/                # optimised photography (see "Photos" below)
index.html            # ← generated
about-us/index.html   # ← generated
...                   # one folder per page, all generated
sitemap.xml           # ← generated
robots.txt            # ← generated
404.html              # ← generated
```

**Generated files are committed on purpose** — GitHub Pages serves them directly, so there
is no CI step and nothing to break on deploy.

## Editing the site

You need [Node.js](https://nodejs.org) installed. There are no dependencies to install.

```bash
# 1. edit the copy
#    src/content.js   — page text, headings, galleries, service cards
#    src/site.js      — phone, address, email, nav menu

# 2. regenerate
node build.js

# 3. preview locally
npx serve .           # or: python -m http.server 8000

# 4. publish
git add -A && git commit -m "Update services copy" && git push
```

GitHub Pages redeploys within a minute of the push.

### Adding a page

Append an object to the array in `src/content.js`:

```js
{
  slug: "outdoor-kitchens",
  title: "Outdoor Kitchens | TJ Specialty Construction | Brainerd, MN",
  description: "One or two sentences for Google and link previews.",
  ogImage: "kitchens-hero",
  blocks: [
    { type: "hero", img: "kitchens-hero", kicker: "Outdoor Kitchens", h1: "Cook outside." },
    { type: "prose", html: "<p>…</p>" },
  ],
}
```

Then add it to `nav` in `src/site.js` if it belongs in the menu, and run `node build.js`.

### Available block types

| Type | Purpose |
| --- | --- |
| `hero` | Full-bleed image banner with headline and buttons |
| `prose` | Body copy (`html`), optionally with kicker/heading |
| `split` | Text beside an image (`flip: true` to swap sides) |
| `cards` | Grid of linked image cards |
| `features` | Grid of short titled blurbs |
| `stats` | Row of large numbers |
| `gallery` | Photo grid with click-to-enlarge lightbox |
| `quotes` | Dark testimonial band |
| `logos` | Greyscale logo strip |
| `ctaBand` | Yellow call-to-action band |
| `raw` | Arbitrary HTML (used for the contact and application forms) |

Any block accepts `bg: "mist"` or `bg: "ink"` to change its background.

## Forms

Both the contact form and the employment application post to
[FormSubmit](https://formsubmit.co) — free, no account, supports file attachments.

**Activate it once:** submit either form on the live site. FormSubmit emails
`info@tjspecialty.com` a confirmation link. Click it, and submissions start flowing.

**Then harden it.** That first email contains a hashed endpoint like
`https://formsubmit.co/abc123def456`. Put it in `src/site.js`:

```js
formAction: "https://formsubmit.co/abc123def456",
```

and run `node build.js`. This keeps the office address out of the page source, where
scrapers can find it.

To switch providers entirely (Formspree, Netlify Forms, etc.), change `formAction` — the
field names are plain English and will carry over.

## Photos

`assets/img/` holds web-optimised JPEGs — heroes capped at 2200px, cards at 1400px,
quality 82, progressive. Sources were the Wix media library and the Dropbox photo folders.

Filenames are stable and referenced by name in `src/content.js` (without the `.jpg`), so
swapping in a better photo is a straight file replacement — no code change:

```
assets/img/kitchens-hero.jpg      hero banner, kitchens page
assets/img/kitchens-1.jpg …-6     kitchens gallery
assets/img/card-kitchens.jpg      kitchens card on home + services
```

Keep replacements landscape for heroes; CSS crops with `object-fit: cover`, so any
aspect ratio works but very tall images waste bytes.

## Deployment

GitHub Pages, served from the `main` branch root. `.nojekyll` stops Jekyll from
touching the output.

### Going live on www.tjspecialty.com

The domain currently points at Wix. To cut over:

1. Create a file named `CNAME` in the repository root containing exactly:
   ```
   www.tjspecialty.com
   ```
2. At the DNS host, replace the Wix records with:

   | Type | Name | Value |
   | --- | --- | --- |
   | `CNAME` | `www` | `tjspec01.github.io` |
   | `A` | `@` | `185.199.108.153` |
   | `A` | `@` | `185.199.109.153` |
   | `A` | `@` | `185.199.110.153` |
   | `A` | `@` | `185.199.111.153` |

3. In **Settings → Pages**, set the custom domain to `www.tjspecialty.com` and tick
   **Enforce HTTPS** once the certificate is issued (usually under an hour).

Old Wix URLs that no longer exist (`/blog-1`, `/blank`, `/post`, `/fullscreen-page`)
are served as redirect stubs pointing at the homepage, so existing links and search
results keep working.
